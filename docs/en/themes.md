# Recolor Ore screens with a resource pack

[简体中文](../zh-CN/themes.md) · [All guides](../README.md)

Resource-pack authors only need to create JSON files. No game code is required. Themes change colors such as panels, text, buttons and slots; they do not replace screen layouts, item textures or native Minecraft item tooltips.

## One file, three optional color settings

All themes use the same JSON format. You can use `preset`, `palette` and `colors` separately or together in one file.

| Field | Required? | Value | Purpose |
| --- | --- | --- | --- |
| `format` | Yes | The number `1` | The theme file format version. This is neither the Minecraft version nor the resource pack's `pack_format`. |
| `preset` | No | `"default"` or `"light"` | Start with a complete built-in color scheme, useful for switching between dark and light styles. |
| `palette` | No | An object containing primary, secondary or danger colors | Supply a base color and automatically generate matching normal, hover, pressed, edge and text/icon colors. |
| `colors` | No | An object containing colors for specific parts | Change a particular part, such as a panel background, body text or slot. Other colors are not automatically adjusted. |

Write only what you want to change. Omitting `preset` keeps the existing scheme as your starting point; other omitted colors are also preserved. JSON does not allow comments or trailing commas. Field names are case-sensitive.

### `preset`: choose a complete built-in scheme

A preset is a ready-made color scheme. ComposeMC currently includes two, with these fixed names:

| Value | Appearance |
| --- | --- |
| `"default"` | Original Ore style: dark gray panels, light text and green accents. |
| `"light"` | Light style: light gray metal panels, dark text and violet accents. |

For example, this is a **complete file** that switches the target theme to the light scheme:

```json
{
  "format": 1,
  "preset": "light"
}
```

`"light"` names the built-in light scheme. It is not a file path. You cannot put a custom filename, mod ID or another theme ID here; use `palette` and `colors` below to create custom colors.

A `preset` resets the entire scheme before applying the rest of that file. Thus `"preset": "default"` means “start again from the built-in dark colors.” Omit `preset` to keep the existing scheme as your starting point.

![Ore controls using the built-in light scheme](../assets/ore-light.png)

### `palette`: change a family of control states with one color

`palette` currently accepts only these three names:

| Name | Purpose | Automatically adjusts |
| --- | --- | --- |
| `primary` | Main actions and selected states | Normal, hover, pressed, edge and text/icon colors for primary controls; filled tracks; marked and hovered slot colors. |
| `secondary` | Secondary buttons and related controls | Normal, hover, pressed, edge and text/icon colors for secondary controls, plus secondary button pixel bevels. |
| `danger` | Destructive actions such as deletion | Normal, hover, pressed, edge and text/icon colors for danger buttons. |

For example, change the existing theme's primary color to blue while keeping the other colors:

```json
{
  "format": 1,
  "palette": {
    "primary": "#5688D8"
  }
}
```

The library generates matching hover, pressed and edge colors and chooses dark or white text/icons according to the base color's brightness. Panel and body text colors are not changed.

### `colors`: change a specific part

For example, change only the panel and body text:

```json
{
  "format": 1,
  "colors": {
    "panel": "#252B38",
    "text": "#EEF2F8"
  }
}
```

`panel` is the panel background and `text` is the body text color. The [color reference](#color-reference) below explains every supported name without requiring source code.

**`palette.primary` versus `colors.primary`:** the former generates a whole family of primary states; the latter changes only the normal primary color, leaving hover, pressed, edge and text/icon colors untouched. Usually, use `palette` to change an accent family and `colors` to adjust details.

### Use all three together

This is another complete file: start with the light scheme, change violet accents to blue, then set the panel and primary button hover colors explicitly.

```json
{
  "format": 1,
  "preset": "light",
  "palette": {
    "primary": "#5688D8"
  },
  "colors": {
    "panel": "#E6E9EF",
    "primaryHover": "#365C9C"
  }
}
```

A file always applies **`preset` → `palette` → `colors`**, regardless of the order in which you write the fields. Here the final primary hover color is `#365C9C`, overriding the value generated by `palette`.

## Where to put the file

Add theme JSON to a resource pack that supports your Minecraft version. The pack root must already contain a valid `pack.mcmeta`; the theme's `format: 1` does not replace it.

Mod authors assign a “theme ID” to each screen, such as `examplemod:storage`. Before the colon, `examplemod` is the namespace (usually the mod ID); after it, `storage` is the theme name. The corresponding path is:

```text
your-resource-pack/
├── pack.mcmeta
└── assets/
    └── examplemod/
        └── composemc/
            └── ore_themes/
                └── storage.json
```

`examplemod` and `storage` are examples to replace with the values published by the target mod. `assets`, `composemc` and `ore_themes` are fixed directory names. Theme IDs and paths use lowercase letters; a theme name containing `/` maps to subdirectories.

| What you want to change | Path inside the resource pack |
| --- | --- |
| Global default colors | `assets/composemc/composemc/ore_themes/default.json` |
| Default colors for the `examplemod` namespace | `assets/examplemod/composemc/ore_themes/default.json` |
| The `examplemod:storage` theme | `assets/examplemod/composemc/ore_themes/storage.json` |
| The built-in `composemc:light` theme selected directly by a screen | `assets/composemc/composemc/ore_themes/light.json` |

**The filename must match the theme ID actually selected by the screen.** Creating `storage.json` does not automatically attach it to a storage screen; only screens using `examplemod:storage` read it. Look up theme IDs in the target mod's resource-pack guide. If they are not published, the mod author needs to provide them. A mod may share one theme between screens or use the `composemc` namespace, so you cannot infer the path from its mod name alone.

For example, suppose a mod selects `examplemod:storage` for its storage screen and `examplemod:settings` for its settings screen. Set their shared defaults in `assets/examplemod/composemc/ore_themes/default.json`; to change only the storage theme, use `storage.json` in the same directory.

## How files combine

For `examplemod:storage`, colors are applied in this order:

1. Built-in dark colors.
2. Global `assets/composemc/composemc/ore_themes/default.json`.
3. Mod default `assets/examplemod/composemc/ore_themes/default.json`.
4. Named theme `assets/examplemod/composemc/ore_themes/storage.json`.

Missing files are skipped. When several sources provide the same path, the mod's bundled resources and all enabled resource packs contribute files, from lowest to highest pack priority. Later files change only the fields they contain. However, `preset` resets all colors and `palette` regenerates the entire related family, including colors explicitly set by earlier files.

For example, if a lower-priority `storage.json` sets `panel` and `text`, and a higher-priority file at the same path sets only `colors.panel`, the panel changes while the text color is preserved.

**Scope comes before pack order:** a named theme always applies after its namespace default. Even a higher-priority pack's `default.json` cannot replace colors explicitly set in a named theme file. Override that same named path instead. Global defaults follow the same rule.

`composemc:light` is an exception: it starts directly from the built-in light scheme, then applies `assets/composemc/composemc/ore_themes/light.json`, without inheriting the global default. Editing this `light.json` affects only screens selecting `composemc:light`; `"preset": "light"` in other files still uses the library's built-in light values.

## Color reference

Colors use `"#RRGGBB"` or `"#RRGGBBAA"`. The first six digits specify red, green and blue. The optional last two digits specify opacity: `00` is fully transparent and `FF` is fully opaque. For example, `"#00000080"` is roughly half-transparent black and `"#141516D9"` is roughly 85% opaque dark gray. Hex digits may use either case, but the leading `#` is required. Names such as `red`, `rgb(...)` and short values such as `#FFF` are not accepted.

This is the complete list of names accepted inside `colors`. Pick what you need; there is no need to fill in every entry. A color may be shared by several controls; the table describes typical uses. Parts for which a mod supplies fixed colors are not affected by these settings.

| Name | Where it appears |
| --- | --- |
| `backdrop` | Background overlay covering the game world behind the screen. |
| `panel` | Main panels, normal text fields and similar backgrounds. |
| `raised` | Raised surfaces, title bars and some tooltips. |
| `hovered` | Hover backgrounds for list items, icon buttons and similar areas. |
| `edge` | General dark control edges and dividers. |
| `highlight` | Light edges of panels, slots and similar surfaces. |
| `frameEdge` | Outer window frame. |
| `ledge` | Bottom strip giving a window or panel visible thickness. |
| `slot` | Normal item slot background. |
| `slotEdge` | Normal item slot dark edge. |
| `markedSlot` | Marked item slot background. |
| `slotHover` | Color blended into a hovered slot's background. |
| `slotHoverEdge` | Base outline color for hovered or marked slots. |
| `text` | Normal body text and input text. |
| `mutedText` | Secondary descriptions, input placeholders and similar text. |
| `disabledText` | Text on disabled buttons and related controls. |
| `ink` | Dark foreground available to controls or mods; changing it does not automatically change `onSecondary`. |
| `primary` | Normal primary button background, also used for selected states. |
| `primaryHover` | Hovered primary button background. |
| `primaryPressed` | Pressed primary button and related control backgrounds. |
| `primaryEdge` | Dark or bottom edge of primary controls. |
| `onPrimary` | Text, icons and checkmarks on primary backgrounds. |
| `secondary` | Normal secondary button and related control backgrounds. |
| `secondaryHover` | Hover color for some secondary controls; secondary button faces use `secondaryButtonActive`. |
| `secondaryPressed` | Pressed color for some secondary controls; secondary button faces use `secondaryButtonActive`. |
| `secondaryEdge` | Dark or bottom edge of secondary controls. |
| `onSecondary` | Text and icons on secondary backgrounds. |
| `danger` | Normal danger button background, also used for input errors. |
| `dangerHover` | Hovered danger button background. |
| `dangerPressed` | Pressed danger button background. |
| `dangerEdge` | Dark or bottom edge of danger buttons. |
| `onDanger` | Text and icons on danger buttons. |
| `buttonBorder` | Button outer frame, also used for scrollbar thumb frames. |
| `secondaryButtonActive` | Secondary button face while hovered or pressed. |
| `secondaryButtonLightEdge` | Top and left bevel of secondary buttons. |
| `secondaryButtonDarkEdge` | Bottom and right bevel of secondary buttons. |
| `secondaryButtonCorner` | Transition pixels at the top-right and bottom-left corners of secondary buttons. |
| `bevelLight` | Reference color used when blending generated control highlights, usually white. |
| `switchTrack` | Unchecked switch track, also used by unselected radio controls. |
| `trackFilled` | Filled portion of a slider track. |
| `trackFilledLight` | Light edge of a slider's filled track. |
| `trackEmpty` | Unfilled portion of a slider track. |
| `trackEmptyLight` | Light edge of a slider's unfilled track, also used by scrollbar rails. |
| `disabledEdge` | Disabled control edges. |
| `focus` | Outline for keyboard or input focus. |

Values inside `colors` do not update each other: changing body `text` does not change button text `onPrimary`, and changing `slot` does not regenerate hover colors. `palette` is calculated before `colors`, so `colors.slot` and `colors.bevelLight` in the same file do not retroactively affect generated colors either. Set the corresponding exact colors to adjust those details.

## Apply changes and troubleshoot

Place the pack in the current game instance's `resourcepacks` directory and enable it in the resource-pack settings. After editing files, press **F3+T** to reload. Open screens retain text drafts, scroll positions and menu bindings. Removing the pack and reloading also removes its color overrides.

If a change does not appear, check these in order:

1. Does the file path match the screen's theme ID? Is a named theme overriding `default.json`?
2. Is the pack enabled? Does a higher-priority pack override the same path?
3. Is the JSON valid, with `"format": 1`, a `preset` of `"default"` or `"light"` if present, and valid color names and values?
4. Does the game instance's `logs/latest.log` contain `Skipping Ore theme`? The message includes the resource path, source pack and error reason.

Unknown fields, invalid colors, unknown presets or broken JSON cause that source's entire theme file to be skipped. Valid files from other sources still apply. Theme files load only on the client.

## Mod developers: publish your screen theme IDs

This section covers code integration. Resource-pack authors only need the steps above.

```kotlin
import dev.composemc.ui.ore.theme.OreThemeId

ComposeScreen(
    Component.literal("Storage"),
    theme = OreThemeId("examplemod", "storage"),
) {
    OreScreen("Storage") { /* controls */ }
}
```

Publish “screen name → theme ID → JSON path” in your mod's resource-pack guide, for example “Storage → `examplemod:storage` → `assets/examplemod/composemc/ore_themes/storage.json`.” Bundle defaults at the same path under your mod's `src/main/resources` so resource packs can override them.

`ComposeMenuScreen`, `ComposeInventoryScreen`, `ComposeHudLayer` and `ComposeConfigScreen` also accept `theme`. Ordinary entry points default to `composemc:default`; config screens use the supplied ModContainer's `<modid>:default`. Ownership is explicit rather than inferred from class names.

Dialogs, menus and Compose tooltips inherit the current theme. For a local theme, use `OreTheme(id = OreThemeId("examplemod", "inspector")) { … }`. `OreScreen` handles layout and uses inherited colors; `OreThemeId.Light` selects `composemc:light` as described above.

`OreTheme(colors = …)` supplies literal colors; use named themes for resource-pack control. Desktop hosts can provide an immutable `OreThemeCatalog` through `OreThemeResources`. Resource reload reads and validates files during preparation, publishes a complete snapshot during apply, and updates the existing screen on its Compose thread without recreating the UiSession. Equal snapshots do not trigger theme recomposition.
